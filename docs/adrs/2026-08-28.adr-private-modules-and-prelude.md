# ADR: Private modules with a prelude facade

- Date: 2026-08-28
- Status: Accepted
- Scope: `terminal-core` crate API surface (`src/lib.rs`)

## Context

`terminal-core` initially declared every module `pub` and re-exported a handful
of types at the crate root. That makes the entire module tree part of the public
API: every `pub` item in every module — helper functions, constants, field-level
details, module paths themselves — becomes something a consumer can depend on,
and therefore something that cannot change without a breaking release. For an
engine still growing (VT parser, alternate screen, FFI copy-out, the maintenance
thread), that is a brittle surface: internal refactors would ripple outward
needlessly.

There is no external consumer yet, so tightening the surface now is free.

## Decision

The implementation modules (`cell`, `color`, `cursor`, `geometry`, `grid`,
`logical_line`, `screen`, `scrollback`, `text`) are **private** (`mod`, not
`pub mod`). The crate's entire public API is a single `pub mod prelude` that
re-exports the intended types and nothing else:

`Cell`, `CellAttrs`, `Color`, `Cursor`, `Position`, `TerminalSize`, `Grid`,
`AttrRun`, `LineId`, `LogicalLine`, `Pen`, `Row`, `Screen`, `Scrollback`.

Consumers write `use terminal_core::prelude::*;`.

Items that were `pub` only for intra-crate use — the `text` width/segmentation
functions and the `scrollback` capacity constants — are deliberately left out of
the prelude. They remain `pub` within their now-private modules, which keeps them
reachable across the crate while invisible to consumers.

## Consequences

- Module internals (field layouts, private helpers, even which module a type
  lives in) can be refactored without a breaking change, because only the
  prelude re-exports are load-bearing externally.
- Adding something to the public API is now a deliberate act: add a line to the
  prelude. Nothing leaks by default.
- Intra-doc links from public items must target the public path
  (`crate::prelude::Grid`), not the private module path, to avoid a rustdoc
  private-link warning. `screen.rs` was updated accordingly.
- Intra-crate `use crate::<module>::…` paths are unaffected: private modules are
  still reachable from within the crate.
