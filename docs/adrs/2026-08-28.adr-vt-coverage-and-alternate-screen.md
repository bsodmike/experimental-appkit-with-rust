# ADR: VT coverage — margins, modes, replies, and the alternate screen

- Date: 2026-08-28
- Status: Accepted
- Scope: `terminal-core` `parsers::vt` and `screen`
- Follows: `2026-08-28.adr-vt-parser-nom-streaming.md`

## Context

The first parser slice covered printable text, C0, cursor moves, erase and SGR.
That is enough for a shell echoing lines and not much else: `vim`, `less`, `top`
and anything using a status line need scrolling margins, a saved cursor, DEC
private modes, answers to their queries, and the alternate screen. This ADR
records the decisions taken while filling that in, all of which were about *what
the engine owes whom*, not about parsing.

## Decisions

### Margins bound the scroll, and the scroll decides what becomes history

`DECSTBM` gives `Screen` a top and bottom margin. The line feed, the autowrap
path and `IND`/`RI` all scroll the region rather than the screen.

**Rows scrolled out of a partial region are dropped, not pushed to scrollback.**
Scrollback is the history of the session, not of a pane: when a program has
carved out a region — a pager's text area above a status line — what falls out
of that region is that program's business. Only a whole-screen region feeds
scrollback. `IL`/`DL` never feed it either, for the same reason.

A resize resets the margins to the whole screen. Margins are display
coordinates, and after a reflow they no longer mean what the program that set
them intended.

### Modes are terminal state, buffers are not

`Modes` (DECCKM, DECKPAM, DECAWM, DECTCEM, bracketed paste) lives on the
terminal, alongside the pen, the title and the pending replies. Rows, cursor,
margins and the half-frozen straddling line live in a *buffer*. That split is
what makes the alternate screen a swap.

Two modes have teeth today: `DECAWM` off makes the write path park on the last
column and overwrite it instead of wrapping, and `DECTCEM` rides in the render
frame so the caret is snapshotted with the text it sits in. The two keyboard
modes are stored for the key-encoding slice, which is where they are read
(PRD §5: key encoding is engine state).

### Parsing has an output side, and it is returned, not stashed

`Screen::advance` returns the bytes owed to the program. PRD §9 asks for exactly
this: a program that sends `CSI 6 n` *blocks* until it is answered, so an
ignored answer shows up as a hang rather than an error. `#[must_use]` makes
dropping it deliberate. `take_replies` remains for callers driving
`Screen::apply` directly.

The queue is capped (4 KiB) and overflow is dropped. A program can ask faster
than anyone drains, and an unbounded queue would be a memory leak driven by
untrusted output.

Answers: `CSI 5 n` → `CSI 0 n`; `CSI 6 n` → `CSI row ; col R`, 1-based; `CSI c`
→ `CSI ? 6 c`, a VT102, which is roughly what the engine implements. Anything
else is left unanswered — an invented answer is worse than none.

### The alternate screen is a swapped buffer, not a `Grid`

PRD §17.5 #21 said the dumb `Grid` would back the alternate screen. It does not.
Setting the primary `Buffer` aside and swapping in a blank one gives the
alternate screen the identical write path — wide characters, combining marks,
scroll regions, line editing — where a separate `Grid` would need every one of
those operations reimplemented against a second type, or a trait indirection
through both. `Grid` stays as the scratch rectangle it always was.

The alternate screen keeps no history: rows scrolled out of it are dropped, and
the scrollback written before the switch is untouched by it, because scrollback
belongs to the terminal rather than to a buffer. `?1049`, `?1047` and `?47` are
all treated the same; `?1049`'s save-and-restore of the cursor falls out of
stashing the whole primary buffer, so no separate save slot is needed. `?1048`
(save the cursor only) is not implemented.

A resize reflows the stashed primary through the normal path — otherwise
returning to the shell would show a screen laid out for the old width — but only
*clips* the alternate screen, whose content belongs to a program that will
redraw it, and rewrapping it would invent lines that program never wrote.

### RIS resets the terminal, not the user's history

`ESC c` returns to the primary buffer, resets pen, modes, margins and the DECSC
stash, homes the cursor and clears the display. Scrollback and the window title
survive: a program claiming the screen is not erasing the user's history, and
the window's title still belongs to the window.

### Titles are untrusted input

`OSC 0` and `OSC 2` set the title, stripped of control characters (a title must
never be able to redraw anything) and bounded to 512 characters. `OSC 1` (icon
name alone) has no place in this UI and is dropped, as are the other OSC
commands — colour queries, hyperlinks, the working directory.

### A private prefix never reaches the standard dispatch

`CSI ? 3 r` is XTRESTORE, not a scroll region; `CSI ? 1 J` is DECSED, not an
erase. Any `<`, `=`, `>` or `?` prefix is routed to a separate dispatch, where
only DEC private mode set/reset is acted on. Without that guard, one private
sequence would have silently rearranged the screen.

## Coverage after this slice

Implemented: printable UTF-8; C0; cursor moves including CHA/HPA/VPA; erase
(ED/EL/ECH); SGR; DECSTBM with IND/RI/NEL, SU/SD, IL/DL, ICH/DCH; DECSC/DECRC
(and the SCOSC/SCORC spelling); DEC private modes 1, 7, 25, 47/1047/1049, 2004;
DECKPAM/DECKPNM; RIS; DSR 5/6 and primary DA; OSC 0/2.

Still deferred: DCS, mouse reporting, character sets (`ESC ( B` and friends are
consumed and ignored), secondary DA, `?1048`, origin mode (DECOM), insert mode
(IRM), tab stops (HTS/TBC — the tab is fixed at every eight columns), and
selective erase.
