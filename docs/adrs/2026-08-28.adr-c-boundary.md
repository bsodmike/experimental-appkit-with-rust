# ADR: the C boundary

- Date: 2026-08-28
- Status: Accepted
- Scope: the new `terminal-ffi` crate, its generated header, and the C smoke test

## Context

PRD §4, §6, §10, §11, §12 and §14 describe the boundary in detail; this slice
builds it. What follows records the decisions those sections left open, and one
place where the generated header caught a defect that a hand-written one would
have hidden.

## Decisions

### The handle owns the whole terminal, and destroying it is the shutdown

`TerminalSession` (the opaque handle) owns the `Terminal` from `terminal-pty`,
which owns the pty, the child and the reader thread. `terminal_destroy` drops
it, and that drop runs the ordered shutdown of PRD §7 — join the reader, hang up
the child — so there is no way to destroy the handle while a thread is still
writing into it. There is deliberately no separate `terminal_shutdown`: PRD §7
allows a destroy that does it all internally and calls that the safer option.

The handle also carries the reusable `Frame`, so the redraw path allocates
nothing after the first frame.

### One copy-out call, two buffers, sized by asking

`terminal_copy_frame` takes the caller's run array and text buffer and fills
both under one lock, so a frame can never tear between row 3 and row 40. The
info struct is filled in *even when the buffers are too small*, which makes the
sizing call (`buffers = NULL`) and the copying call the same function. Nothing
is allocated for the caller, so there is nothing to free and no second lifetime
to get wrong (PRD §10-A). `terminal_copy_title` follows the same shape for
text (PRD §11).

Lengths and capacities cross as `u32`, not `usize`: the layout must not depend
on the target's pointer width (PRD §4.2).

### The FFI types are its own, not the engine's

`terminal-ffi` declares `TerminalRun`, `TerminalSize` and the rest itself and
converts, rather than re-exporting the engine's types through cbindgen's
dependency parsing. The header then names things as a C API should, and the
engine stays free to change its own layouts. The conversion is free in practice:
it happens during the copy that was going to happen anyway.

### Keys cross as data, not as a tagged union

`TerminalKeyEvent` is a flat struct — a code enum plus a `codepoint` and a
`number` — rather than a C tagged union. Only two variants carry a payload
(`Char` and `F`/keypad digit), and a flat struct is something an Objective-C
`switch` can fill in without ceremony.

### Errors are statuses, panics are caught, and null is never fatal

Every fallible entry point returns `TerminalStatus` (`#[repr(i32)]`), checks
every pointer it is given, and wraps its body in `catch_unwind`. Unwinding out
of an `extern "C"` function aborts since Rust 1.81, and aborting kills the
user's session — a safety net, not a solution (PRD §12).

`terminal_send_text` passes bytes through without validating UTF-8: the shell is
entitled to whatever the user typed. `terminal_paste` *does* validate, because
the engine has to reason about the text to frame it.

### The wake-up context is trusted, and the contract is written down

The context pointer crosses threads (the callback runs on the reader thread), so
it is wrapped in a type with `unsafe impl Send + Sync`. Rust never dereferences
it. The contract the frontend must honour — valid until `terminal_destroy`
returns, safe to touch from another thread — is documented at the wrapper, since
that is the promise the `unsafe impl` is making.

The wrapper exposes the pointer through a method rather than a field, so the
closure captures the wrapper (which carries the promise) rather than the bare
pointer (which does not). Without that, the closure does not compile — which is
the borrow checker enforcing exactly the right thing.

### Generating the header caught the first bug

`Option<TerminalWakeUpFn>` — an idiomatic nullable function pointer in Rust —
came out of cbindgen as an *opaque struct*, which C could not have filled in.
Spelling the field as `Option<extern "C" fn(ctx: *mut c_void)>` produces
`void (*wake_up)(void *ctx)`. A hand-written header would have said the right
thing while the library expected something else, which is precisely the silent
corruption PRD §14 warns about.

### A C smoke test, on Linux

`examples/smoke.c` creates a terminal, receives a wake-up, copies a frame and
destroys the handle, and `examples/run-smoke.sh` links it against the staticlib
using the exact library list `--print native-static-libs` reports (PRD §14,
gotcha 4). It is the §14 pipeline in miniature, and it proves the header and
the library agree without needing a Mac.

## Deferrals

- No `terminal_last_error_message` yet (PRD §12 offers it as optional). Statuses
  say what went wrong in the categories the frontend can act on.
- No pointer/selection entry point yet: selection state is a later slice, and
  `terminal_pointer_event` arrives with it.
- Scrollback is not reachable from the boundary — the frame is the visible
  screen only, until the scrolled-back viewport exists.
