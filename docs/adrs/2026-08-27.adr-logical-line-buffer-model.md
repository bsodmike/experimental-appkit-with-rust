# ADR: The logical-line buffer and scrollback storage model

- Date: 2026-08-27
- Status: Accepted
- Scope: `terminal-core` primary-screen buffer, scrollback, and reflow (PRD §16)

## Context

PRD §16 decided that wrapped lines reflow on resize (decision #6) and that
scrollback is stored as logical lines with display rows derived as
`(line_id, offset, len)` (decision #9). It did not resolve *how mutation fits
that storage*, how the active screen relates to scrollback, the concrete
in-memory representation, coordinate units, eviction, the wrap-point cache, the
straddling-line edge case, or the source of grapheme width. This ADR records
the resolution of those, reached by a grilling session, and refines §16.1.

## Decisions

1. **Hybrid model.** The active/primary screen is an owned, mutable grid (the
   single mutation surface for all cursor, scroll-region and edit operations).
   Scrollback is logical lines. `(line_id, offset, len)` is the scrollback and
   reflow representation, not the live-screen representation. This refines
   §16.1, whose wording implied a pure unified model where the primary screen is
   itself derived indices. Rationale: keeping the mutation surface a plain grid
   makes CUP, scroll regions, IL/DL and clears trivial; the logical-line cost is
   paid only at the scrollback boundary and during reflow.

2. **`line_id` born with the logical line.** Allocated when a logical line
   begins, tracked through the active grid (each row tagged with owning
   `line_id` and a soft-`wrapped` flag), and persisted into scrollback.
   Rationale: selection and viewport anchors are `(line_id, offset)` and can
   point at on-screen text, so visible lines need stable identity or resize
   breaks on-screen selections. Monotonic counter, never an array index
   (existing decision #12).

3. **Scrollback stores packed UTF-8 text plus attribute runs**
   (`{ byte_start, byte_len, cols, fg, bg, attrs }`), immutable, converted from
   grid rows on eviction. Rationale: at the 100k ceiling (#13) a `Vec<Cell>`
   with per-cell heap content is hundreds of MB; packed lands at a few MB and is
   already the §10 render-run shape, so the read path is nearly a memcpy.
   Immutability is a non-issue because scrolled-off lines are frozen.

4. **Active-grid cell content is `compact_str::CompactString`, not heap
   `String`.** Reverses the earlier per-cell `String` choice. Rationale: keeps
   content UTF-8 (consistent with packed scrollback and §10 runs) while
   eliminating a heap allocation per cell for all real grapheme clusters
   (<= 24 bytes inline).

5. **One internal offset unit: byte offsets into the packed UTF-8,
   grapheme-aligned.** Used for both display-row triples and anchors; §16.2's
   `char_offset` becomes a byte offset. Display columns are computed on demand by
   the width scan (rendering, DSR, hit-testing), never stored. Rationale: O(1)
   slicing for the read path, width-independent so stable across reflow, and
   columns as a stored unit would be reflow-unstable.

6. **A dedicated `Screen` type for the primary buffer** (row-oriented storage,
   each row bundling its cells with `{ line_id, wrapped }`, owning the cursor and
   the scrollback). The existing dumb `Grid` rectangle is kept for the alternate
   screen and scratch, which never reflow and have no line identity. Two types
   because their requirements differ.

7. **Dual scrollback cap.** Primary limit is logical-line count (default 10k,
   max 100k, per #13); secondary safety limit is total packed bytes across
   scrollback. Eviction removes whole oldest logical lines from the front of a
   `VecDeque`; lines are never split or truncated. Rationale: a logical line is
   unbounded, so a count cap alone is not a memory bound; the byte cap defends
   against pathological single lines. Monotonic `line_id` makes an anchor into an
   evicted line detectably stale.

8. **Wrap-point cache.** Per logical line, an optional
   `{ width, row_starts }` where `row_starts` are grapheme-aligned byte offsets
   of each display-row start, stored inline (small-vector, no per-line heap
   allocation for the common short line). Invalidated by comparison against a
   single global current-width, not by clearing, so a resize invalidates all
   lines in O(1). Filled lazily on demand and proactively by the §16.5
   maintenance thread. Scrollback only; active rows are already materialised.
   This cache is the concrete mechanism of §16.4 lazy reflow.

9. **Straddling-line handling: allow split, rejoin by `line_id`.** As each top
   row scrolls off it is packed and appended to its `line_id`'s scrollback entry,
   so the active grid stays a clean fixed rectangle. At most one line (the top
   visible one) is ever split between a frozen head in scrollback and a live tail
   in the grid; it is reconstructed by concatenating head+tail whenever reflow or
   anchor resolution needs the whole line. The frozen head is safely immutable
   because the cursor cannot address above the viewport; reflow always re-derives
   from head+tail, so they never disagree. The frozen head's byte length is
   tracked so split-line byte anchors resolve against the concatenated whole.

10. **Grapheme width and segmentation have one authority.** `unicode-width`
    (with terminal rules layered on: VS16 forces width 2, combining marks
    contribute 0, regional-indicator pairs are 2) behind a single
    `grapheme_width(cluster) -> u16`, and `unicode-segmentation` behind a single
    segmenter. Rationale: the write path and the reflow scan must compute width
    and cluster boundaries identically or the display desyncs; a single shared
    function is the correctness invariant, not merely tidiness. Ambiguous-width
    defaults to 1, configurable post-MVP.

## Consequences

- New dependencies: `compact_str`, `unicode-width`, `unicode-segmentation`.
- `crates/terminal-core/src/cell.rs` changes: `content` becomes `CompactString`.
- New modules ahead: `Screen` (primary buffer), the packed logical line plus its
  run and wrap-cache types, the width/segmentation authority, and the eviction
  logic. `Grid` and `Cursor` are unchanged and remain the alternate-screen and
  cursor primitives.
- The §16.5 maintenance thread's concrete job is now defined: fill and refresh
  per-line wrap caches for scrollback in the background.
- PRD §16.1 is refined (hybrid, not unified) and §17 gains these as settled
  decisions.
