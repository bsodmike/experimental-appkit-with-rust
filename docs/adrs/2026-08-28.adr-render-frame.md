# ADR: the render frame — runs, one text buffer, and a `row` field

- Date: 2026-08-28
- Status: Accepted
- Scope: `terminal-core` `render` (`prelude::Frame`, `prelude::Run`), `Color::pack`

## Context

PRD §10 settles *how* the frontend reads the screen (option A: the caller owns a
buffer, the engine copies into it under the lock) and *what* it reads (runs, not
cells). What it left open is the Rust-side shape that the FFI copy will read
from, and two details the sketch in §10 could not decide in the abstract: how a
colour becomes the `u32` on the wire, and how a flat array of runs says which
row each run belongs to.

The engine must stay headlessly testable (PRD §18), so the frame is built and
tested here, in pure Rust, well before any `extern "C"` exists.

## Decision

- **A `Frame` owns one `String` and one `Vec<Run>`.** Every run in the frame
  slices the same text buffer by `(utf8_offset, utf8_len)`. Two buffers is
  exactly what the §10-A call will copy — the FFI adds no new shape.
- **`Screen::render_into(&mut Frame)` is the redraw path**; it clears the buffers
  but keeps their capacity, so a frontend reusing one frame allocates nothing in
  the steady state. `Screen::render()` is the allocating convenience.
- **`Run` gains a `row: u16` field**, which the PRD's original sketch did not
  have. The alternative was runs plus a parallel per-row index array, which
  would make the copy-out API two buffers, two capacities and two lengths
  instead of one. Field order is chosen so `Run` packs to 24 bytes with no
  padding.
- **Colours are packed with a tag byte, not resolved.** `Color::pack` gives
  `0x00_000000` for the terminal default, `0x01_0000II` for a palette index and
  `0x02_RRGGBB` for truecolour. The engine never bakes in a theme, so `Default`
  has to survive the boundary as something the frontend can still recognise.
- **The cursor position travels in the frame**, captured in the same snapshot as
  the runs, so the caret can never disagree with the text under it.
- **Coalescing rules.** Trailing blanks are dropped. A blank cell joins the
  current run when the run's own style would draw nothing on it, so
  `hello world` is one run. An all-blank run adopts the style of the first cell
  that actually draws, provided that style is invisible on spaces, so leading
  indentation stays attached to its text. The spacer column of a wide grapheme
  adds a column and no bytes.

## Consequences

- `cols` counts display columns and `utf8_len` counts bytes; they differ for
  wide graphemes and for combining marks, which is precisely why the frontend
  positions by cell and draws by run (PRD §10).
- Blank columns between runs carry no bytes: the frontend paints its default
  background and skips to the next run's `col`. `Frame::row_text` reconstructs
  the gaps with spaces for tests and for copy-out of a display row.
- A zeroed run reads as "default on default", which is the harmless reading for
  a frontend that forgets to fill a field.
- Colour resolution (palette index and `Default` to concrete RGB) is now
  unambiguously the frontend's job.

## Deferrals

Damage tracking (§5: which rows changed since the last draw) is not in the frame
yet — every render walks all visible rows. Selection highlighting, the alternate
screen and scrollback offset (rendering a scrolled-back viewport rather than the
live rows) arrive with their own slices.
