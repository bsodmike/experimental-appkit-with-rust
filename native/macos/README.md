# Crustty, the macOS app

The AppKit frontend for the terminal engine in `crates/`. If you want to know
*why* any of this is shaped the way it is, read `docs/PRD-mac.md`; if a macOS
concept in that document is unfamiliar, `docs/PRD-mac-01-concepts.md` explains
it. This file is only about how to build and run the thing.

## First time

```sh
just doctor      # what is installed, what is missing, what this machine is
just bootstrap   # brew install just xcodegen watchexec
just test        # Rust tests, glue tests, then the Xcode tests
just run         # build everything and launch, with logs in this terminal
```

No Apple Developer account is needed for any of that. The app is signed
ad-hoc, which is valid on this Mac and meaningless anywhere else — which is all
a development build needs.

## The commands

| Command | What it does |
|---|---|
| `just` | List everything |
| `just build` | Cargo, then XcodeGen, then `xcodebuild` (Debug) |
| `just run` | Build, then run the binary directly so its log output lands here |
| `just watch` | Rebuild and relaunch on any change to `.rs`, `.cpp`, `.mm`, `.h`, `.yml` |
| `just xcode` | Generate the project and open it, for breakpoints and Instruments |
| `just test` | Everything testable on this machine |
| `just test-glue` | Only the platform-free frontend core — the tier that also runs on Linux |
| `just release` | A Release build, ad-hoc signed, in `build/Release/Crustty.app` |
| `just clean` | Cargo's output, the build directory, the generated project |

For fish completion:

```fish
just --completions fish > ~/.config/fish/completions/just.fish
```

## What you are looking at

```
native/macos/
  project.yml      the Xcode project, as something you can read
  Glue/            plain C++ — every decision the frontend makes
  Sources/         Objective-C++ — AppKit, and as little thinking as possible
  Tests/
    glue_tests.cpp  runs here and on Linux, against the real static library
    AppKitTests.mm  the small tier that genuinely needs a Mac
  build/           generated; not committed
  Crustty.xcodeproj  generated by `just xcode`; not committed
```

**The `.xcodeproj` is disposable.** It is generated from `project.yml` every
time. Anything you change in Xcode's own project settings UI is lost on the
next `just xcode` — change `project.yml` instead. That is the trade: the file
you can read is the one that counts.

## Configuration

Settings come from `NSUserDefaults`, so you can change them without rebuilding:

```sh
defaults write com.inertialbox.crustty fontName -string "SF Mono"
defaults write com.inertialbox.crustty fontSize -int 15
defaults write com.inertialbox.crustty shell -string /opt/homebrew/bin/fish
defaults write com.inertialbox.crustty optionIsMeta -bool false
```

Unset values fall back to the system monospaced font at 13pt, `$SHELL`, and
Option-as-Meta. A font size outside 6–72 is clamped rather than obeyed. Reset
everything with `defaults delete com.inertialbox.crustty`.

Font size also responds to ⌘+, ⌘− and ⌘0, which is not persisted.

## Checking it works

`just test` covers what can be automated. The rest needs eyes:

1. `just run` — a window appears with a shell prompt in it
2. Type `ls` and press Return — output appears, colours included
3. Drag the window edge — text reflows as you drag, not after
4. `vim`, then `:q` — full-screen redraw, and the screen comes back
5. `printf '\033[31mred\033[0m\n'` — red text
6. Paste a multi-line block with ⌘V — it arrives as one paste, not as commands
7. ⌘+ and ⌘− — the grid grows and shrinks, the window does not move
8. `exit` — the window closes and the app quits
9. `kill -9 $$` — the window **stays open** so you can read the screen, and the
   title says `[killed: SIGKILL]`

Step 9 is the one worth doing deliberately: a shell that dies from an error
prints the error immediately before dying, and taking that off screen is the
least helpful possible moment.

## When it does not build

**`cargo: command not found` during an Xcode build.** Xcode's build phases do
not run your login shell, so they do not have your `PATH`. The pre-build script
sets it explicitly; if cargo lives somewhere unusual for you, add it there in
`project.yml`.

**Undefined symbols at link time.** Rust's standard library pulls in system
libraries, and the authoritative list comes from the compiler:

```sh
just native-libs
```

Add anything missing to `OTHER_LDFLAGS` in `project.yml`.

**The app builds but the shell does not start.** Check `$SHELL` is what you
think, and try `defaults write com.inertialbox.crustty shell -string /bin/zsh`.
A Debug build shows the engine's own error on screen when this happens.

**Something changed in Rust but the app did not notice.** The pre-build script
declares its inputs, and those are the crate roots rather than every file. If
you edited a module and nothing rebuilt, `just clean && just build`.

**XcodeGen fails or the project will not open.** Check `just doctor` for the
XcodeGen version. This project uses only long-standing keys, but XcodeGen does
occasionally lag a new Xcode release.

## Before the first signed release

Three things, none of which matter until you distribute the app to another
machine:

1. **The bundle identifier is permanent.** `com.inertialbox.crustty` keys
   preferences, keychain items and permissions. Changing it after shipping
   orphans all three.
2. **Signing.** Copy `Local.xcconfig.example` to `Local.xcconfig` and fill in a
   Developer ID identity. Then `just release-signed`.
3. **Notarization.** Store credentials once:

   ```sh
   xcrun notarytool store-credentials crustty-notary \
       --apple-id you@example.com --team-id ABCDE12345
   ```

   Then `just dmg && just notarize`.

The Mac App Store is not a target, and cannot be: it requires the App Sandbox,
a sandboxed process's children inherit the sandbox, and a shell that cannot
read your home directory is not a shell. `Crustty.entitlements` says the same
thing in the file where someone would look.
